# Tests

## Unit tests

`npm test` runs `tests/**/*.test.ts` with Node's built-in runner (Node strips the types: no `enum` or parameter properties in modules tests load). `tests/setup.mjs` runs first: it points `MEDIA_DIR` at a fresh temporary folder (without it `lib/paths.ts` would use `./data`) and registers `tests/hooks.mjs`, which resolves `@/`, extensionless imports and an empty `server-only`, so server modules load. `tests/library.test.ts` runs real ffmpeg on `tests/fixtures/clip.mp4` (a generated 30-second test pattern, 227 KB), and on music it makes itself (a tone, as mp3, mka and wma), and skips without it. The browser tests upload `tests/fixtures/tone.mp3` for music (5 seconds of a tone, a red square for its cover, "The Testers" for its artist, no title; `MUSIC` in `e2e/helpers.ts`).

`npm run typecheck` runs `tsc --noEmit`; `npm run lint` runs Biome's linter (`biome.jsonc`: recommended rules minus the ones listed there with why; formatting left alone). CI (`.github/workflows/ci.yml`) runs lint, typecheck, unit tests and a build, and the browser tests in a job of their own.

## Browser tests

`nix develop .#e2e --command npm run test:e2e` runs `e2e/` with Playwright (`playwright.config.ts`; the `e2e` shell provides nixpkgs' Chromium as `MEDIA_E2E_CHROMIUM`, which plays H.264; CI uses Google Chrome for the same reason, since Playwright's own Chromium has no H.264). It starts `next dev` on :3101 over a temporary library, one test at a time, so stop any `next dev` of yours in this checkout first. `MEDIA_E2E_URL` points it at a running server instead.

YouTube is never reached: `MEDIA_YTDLP` is `e2e/stub-yt-dlp.mjs`, which prints progress the way `lib/downloads.ts` asks for it and "downloads" the fixture clip, titled `Stub video <id>`. The id `unavailable` fails like a removed video. A search (`ytsearchN:<query>`) finds three videos named after the query and a live stream; a playlist search (YouTube's results page) finds two playlists, `PL<query>1` and `2`; the query `nothing` finds nothing. A playlist (`…/playlist?list=<id>`) holds three 30-second videos (`p` + the id's last nine characters + 1, 2, 3) and a private one; an id ending in `missing` doesn't exist. Transmission is `e2e/stub-transmission.mjs` on :3102 (`tests/transmission.test.ts` starts one of its own): four torrents of copies of the fixture clip, reported under `/downloads/complete` as a container would (`MEDIA_TRANSMISSION_PATHS` maps them to the run's temporary folder): a single-file movie, a series with two finished episodes, a 40% one and an `.nfo`, a pdf, and a finished one whose file is missing. It asks for the session id first, as Transmission does; `stub-reset` puts it all back (each test in `e2e/transmission.spec.ts` starts with it) and `stub-removed` lists the torrents removed. `e2e/api.spec.ts` covers the routes without a browser. Add a test there for a new flow.
