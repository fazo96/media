# The API

| Route | |
| --- | --- |
| `GET /api/videos` | Every video (and [music](library.md#music)) |
| `POST /api/upload` | A file: the raw body, its name in `X-Filename` (URI-encoded); `X-Music: 1` adds a video [as music](library.md#added-as-music), `X-Playlists` (ids, comma-separated) puts it at the end of those playlists once it's in. 201 with the video (or music); 415 when it has neither video nor audio (as music: no audio); 400 for a bad `X-Playlists` |
| `GET/PATCH/DELETE /api/videos/<id>` | One video; `{ title?, listen? }`: rename, turn [listen mode](library.md#listen-mode) on or off; move to the trash |
| `GET/HEAD /api/videos/<id>/file` | The video, with `Range` support (206, 416; `lib/range.ts`) |
| `GET/HEAD /api/videos/<id>/audio` | Its audio alone, for [listen mode](library.md#listen-mode) (`audio/mp4`, or `audio/webm` for Vorbis): made on the first request, which waits for it (seconds; a minute to convert), then as `file`. 404 when it has no audio. For music, its file (`listenMime()` in `lib/types.ts`) |
| `POST /api/videos/<id>/music` | Keep only its audio: the video [turns into music](library.md#a-video-turned-into-music), its video file to the trash. Answers when done (seconds; a minute when the audio is converted) with the music; 400 for music already, 415 without audio |
| `GET /api/videos/<id>/thumb` | The still (the page adds `?v=<addedAt>` so a re-download's isn't hidden by the cache) |
| `POST /api/videos/<id>/progress` | `{ position, started?, ended? }`: `started` counts a play, `ended` resets the position. Read as text, so `sendBeacon` works |
| `GET/POST /api/jobs`, `DELETE /api/jobs/<jid>` | YouTube downloads ([downloads](downloads.md)) and imports from Transmission ([transmission](transmission.md)): listed, cancelled and dismissed alike. A download: `{ url, replace?, music?, playlists? }`, 202 `{ job, playlists }`, or `{ video, playlists }` when it's in the library (`playlists` in the answer: the ones it went into, at once) |
| `GET/POST /api/transmission` | Transmission ([transmission](transmission.md)): `{ torrents }` with a video in them; import `{ hash, files, remove?, playlist?, playlists? }` (`files`: indexes in the torrent; `playlist`: put them in a playlist named after the torrent; `playlists`: ids of playlists each goes into too; 202 `{ job }`; 400 for a file that isn't a finished video, 404 for a torrent that's gone, 409 while it's importing). 404 when `MEDIA_TRANSMISSION_URL` isn't set, 502 when Transmission can't be reached |
| `GET/HEAD /api/transmission/<hash>/<index>/file` | A torrent's finished video file, in byte ranges as `/api/videos/<id>/file`, to [preview](transmission.md#the-page) before importing it; 404 for anything that isn't one (or when Transmission isn't set up), 502 when Transmission can't be reached |
| `GET /api/search?q=…` | Search YouTube ([downloads](downloads.md#searching)): `{ videos, playlists }`, up to 20 videos and 6 playlists; 400 for an empty or over-200-character query, 502 with yt-dlp's error, 504 after 60s |
| `GET /api/youtube/playlist?list=…` | A YouTube playlist read whole ([downloads](downloads.md#playlists)), `YoutubePlaylist`, with `playlistId` when it was downloaded before; nothing is downloaded. 400 when `list` isn't a playlist link or id, 502, 504 |
| `GET/POST /api/playlists` | Every playlist, newest first; make one: `{ title }` (201 `{ playlist }`), or `{ youtube: <link or id>, music?, playlists? }` to download a whole YouTube playlist, as music, into other playlists too (201 `{ playlist, jobs, playlists }`; 502, 504 as above) |
| `GET/PATCH/DELETE /api/playlists/<id>` | One playlist; `{ title?, add?, remove?, listen? }` (video ids: `add` must be in the library, and goes at the end; `listen` sets listen mode on every video in it, after those); to the trash, its videos staying |
| `GET/POST /api/shares` | Share links still good, newest first, with their videos' or playlists' titles (`?video=<id>` or `?playlist=<id>`: that one's; cast links aren't listed); make one: `{ video, expires }` or `{ playlist, expires }` with `"1d"`, `"1w"`, `"1m"` or `"never"` (201, the `Share`), or `{ video, cast: true }` for a Cast device (a day long, reused while it has half of that left) |
| `DELETE /api/shares/<token>` | Revoke a link (204; 404 when there's none) |
| `GET/HEAD /api/s/<token>/file`, `GET /api/s/<token>/thumb` | **No session**: a share link's video (as `/api/videos/<id>/file`, `?download` as an attachment named for its title) and still, with `Access-Control-Allow-Origin: *`; 404 once the link has expired or been revoked, and for a playlist link (it has no video of its own) |
| `GET/HEAD /api/s/<token>/audio` | **No session**: a video link's audio alone (as `/api/videos/<id>/audio`), for [casting](pages.md#casting) in listen mode; `Access-Control-Allow-Origin: *`, 404 as above |
| `GET/HEAD /api/s/<token>/v/<id>/file`, `GET /api/s/<token>/v/<id>/thumb` | **No session**: the same for one of a playlist link's videos, while it's in the playlist (checked on every request, `sharedVideo()`); 404 for any other video, and for a video link |
| `GET /api/tools` | yt-dlp, ffmpeg, ffprobe: how each runs, its version |
| `GET /api/storage` | `{ library, trash, free, total }` in bytes ([library](library.md#disk-usage)) |
| `GET/POST /api/auth` | The lock: `unlock`, `set`, `change`, `remove`, `signout` (from pen) |

Every handler but `auth` and `api/s/` is wrapped in `route()` (`lib/route.ts`): the session check, params awaited, `id`, `jid` and `token` validated (404) before it runs. A video's file, audio and still are sent by `lib/serve.ts`, for both `api/videos/` and `api/s/`. It answers with the helpers there (`notFound`, `badRequest`, `fail`, `noContent`, `noStore`) and reads bodies with `readJson`. An `HttpError` (`lib/errors.ts`) thrown from a handler, or from the library under it, is answered as `{ error }` with its status: `NotAVideo` 415, `ToolError` 500 (ffmpeg or yt-dlp failed, or isn't installed), `TransmissionError` 502, `ImportError` its own. `askYoutube()` gives yt-dlp a minute (504 after that, 502 when it fails). The `api/s/` routes are `shareRoute()` (`lib/serve.ts`): the shared video (or, under `v/<id>/`, the playlist link's one) or a 404, sent with `Access-Control-Allow-Origin: *`.

## The proxy and the upload

`proxy.ts` is the first lock check: pages redirect to `/unlock`, API calls get 401. Before it, YouTube's own paths (`/shorts/<id>`, `/playlist`, `/results`…) are redirected to this app's ([pages](pages.md#youtubes-paths)). It lets `/s/…` and `/api/s/…` through: a share link's token is its check (`lib/shares.ts`). Next's proxy buffers a request body only up to `proxyClientMaxBodySize` (10 MB), which would cut videos short, so `api/upload` is left out of its matcher; `route()` is its only check. The upload streams the body straight to `.incoming/` (`stream.pipeline`), so a file's size doesn't matter. A browser giving up mid-upload is answered quietly and its partial file removed.
